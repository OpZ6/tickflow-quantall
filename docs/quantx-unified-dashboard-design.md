# QuantX 统一看板设计与实施计划

状态：设计提案，尚未实现。用于合并现有 QuantX 多日驾驶舱与单日富图表页。

配套视觉原型：[examples/quantx-unified-dashboard-mockup.html](examples/quantx-unified-dashboard-mockup.html)

执行拆分与验证门槛：[quantx-unified-dashboard-execution-plan.md](quantx-unified-dashboard-execution-plan.md)

## 1. 产品目标

QuantX 只保留一个主入口和一个日期上下文。用户进入 `/quantx` 后直接看到最新交易日的完整看板，通过顶部交易日历切换历史日期；不再需要先进入多日驾驶舱，再跳转到 `/quantx/:date` 阅读单日报告。

统一看板同时承载：

- 当日市场状态、风险、仓位与预案；
- 5/10/20 日窗口信号和交易日历；
- 题材、行业、个股的排行与主从钻取；
- 情绪、连板高度、晋级率和溢价率；
- 行业宽度、资金流、拥挤度和机构连续性；
- 关注名单、机会雷达、数据质量和来源覆盖。

## 2. 页面信息架构

页面使用 16 列不对称栅格。每一行根据内容价值决定跨度，不重复套用固定一列或两列模板。

### 2.1 固定顶部上下文

- `QuantX 市场驾驶舱` 标题；
- 前一交易日、日期选择器、后一交易日、回到最新；
- 5/10/20 日观察窗口；
- 数据时间、覆盖率、质量状态和更新入口；
- 日期变化同时切换所有当日与多日组件。

### 2.2 首屏决策层

首屏必须在 5 秒内回答市场强弱、主线、情绪、风险和仓位：

- 一行紧凑指标带：主要指数、涨跌家数、成交额、涨停、最高板、晋级率、市场热度；
- 市场脉搏：全 A 趋势、成交额和涨跌家数的组合图；
- 题材主线：可排序题材排行，并显示强度、涨跌家数、龙头和连续性；
- 今日决断：仓位、市场阶段、风险触发和次日动作。

### 2.3 第二屏分析层

- 多日信号矩阵：5/10/20 日按市场、情绪、题材、资金、机构五类展示；
- 情绪时间轴：热度、短线情绪、趋势情绪、连板高度、晋级率合并；
- 机会雷达：题材、行业和个股机会统一排序；
- 行业宽度：一级/二级切换，5/10/20/60 日热力图；
- 资金生态：行业资金流、散点和 treemap 在同一卡片切换；
- 关注池：候选、触发条件、风险和预案。

### 2.4 深度数据层

原单日报告的全部富图表不删除，但移入同页底部的页签工作区：

- 市场趋势；
- 题材与行业；
- 情绪与连板；
- 资金生态；
- 关注名单；
- 完整数据表。

默认只渲染当前页签的重型 ECharts，避免 12 张图同时初始化。

### 2.5 桌面端精确排版

桌面端内容区使用 16 列，不把页面抽象成重复的一列或两列。以下跨度是 1440px 以上的目标值，实际组件可按内容密度微调：

| 行 | 高度目标 | 左侧 | 中部 | 右侧 |
| --- | --- | --- | --- | --- |
| 固定顶栏 | 48–56px | 标题与数据状态 | 前后交易日、日历选择、最新 | 5/10/20 窗口、刷新、质量 |
| 指标带 | 52–64px | 跨 16 列；8–12 个紧凑指标自动均分，不换成大卡片 |
| A：首屏决策 | 300–340px | 市场脉搏 6 列 | 题材主线 6 列 | 今日决断 4 列 |
| B：多日与情绪 | 240–280px | 多日信号矩阵 5 列 | 情绪周期时间轴 7 列 | 机会雷达 4 列 |
| C：宽度与资金 | 300–340px | 行业宽度 7 列 | 资金生态 5 列 | 关注池 4 列 |
| D：完整分析工作区 | 按活动内容 360–620px | 跨 16 列；页签切换完整富图表、表格与质量血缘 |

目标不是强制所有卡片等高，而是让同一视觉行的主要边界对齐。排行表、信号表和关注池内部允许独立滚动；主页面不使用横向滚动。

### 2.6 顶部日期与全局控制

顶栏始终固定，包含：

1. 前一交易日、后一交易日；
2. 日期输入和 30 日交易日历弹层；
3. 日历格显示当日热度和发布状态；
4. “最新”按钮；
5. 5/10/20 日全局窗口；
6. 事实覆盖、来源降级、生成时间、发布状态；
7. 刷新数据和重建多日派生数据；
8. “紧凑 / 全部展开”切换。

日期改变后，指标带、当日分析、多日窗口、题材行业、机会雷达、关注名单和数据血缘同时切换。不得出现部分卡片仍停留在上一交易日。

### 2.7 指标带完整内容

指标带按可用宽度自动显示，至少保留：

- 所有主要指数名称、收盘和涨跌幅；
- 上涨、下跌、平盘家数；
- 全市场成交额；
- 涨停家数、跌停家数、封板率；
- 最高连板及高度股；
- 晋级率和溢价率；
- 市场热度、短线情绪、趋势情绪及区间；
- 拥挤度；
- 建议仓位。

宽度不足时使用两行指标带或水平滚动指标带，不静默删除指标。每项保留单位、空值和状态语义。

## 3. 全量内容保留与落位

下面是实现时的强制保留矩阵。`首屏` 表示无需额外点击即可看到；`同页页签` 表示仍在 `/quantx` 当前日期页面内；`详情抽屉` 用于明细和原始记录。三者都不是独立报告页面。

| 现有内容 | 新位置 | 展示方式 |
| --- | --- | --- |
| 问财题材排行 | 题材主线 | 与同花顺热点并列来源列，保留名称、数量、排名 |
| 同花顺热点排行 | 题材主线 | 与问财排行对齐，不把两源混成不可追溯分数 |
| 百日新高股票 | 题材详情 / 关注池 | 保留代码、名称、涨跌幅 |
| 当日题材结构 | 题材主线 | 主榜显示来源数、强度、连续日、生命周期 |
| 跨日题材生灭事件 | 题材主线详情 | 出生、增强、衰退、退出分别显示 |
| 题材连续性热力图 | 题材主线 / 深度页签 | 首屏显示 Top 行，完整矩阵保留全部日期和题材 |
| 涨停因子归因 | 题材详情 | 横向条形排行，保留因子计数 |
| 题材机会雷达 | 机会雷达 | 保留评分、活跃日、最近出现日、覆盖率 |
| 行业机会雷达 | 机会雷达 | 与题材、个股同卡页签切换 |
| 个股机会雷达 | 机会雷达 | 保留代码、名称、评分、活跃日、来源 |

题材或行业被选中后，右侧详情至少包含：当日排名、多源证据、5/10/20 日连续性、生命周期、相关因子、行业资金、龙头和核心个股。缺少历史成分时明确显示覆盖率，不能拿当前成分替代。

### 3.5 资金、机构与连续性

| 现有内容 | 新位置 | 展示方式 |
| --- | --- | --- |
| 行业流入/流出横向条形图 `SectorFlowChart` | 资金生态 | 保留 Top In / Top Out 和正负方向 |
| 行业资金 treemap | 资金生态 | 与散点同卡切换，保留净流入和涨跌幅 |
| 行业涨跌幅 × 净流入散点 | 资金生态 | 保留象限、标签和点大小 |
| 行业资金连续性 | 资金生态“连续性”页签 | 保留活跃日、累计净流入、最新涨跌、最近出现日 |

### 3.6 关注名单与行动区

候选记录完整保留：

- 代码、名称；
- 连板次数；
- 入选原因；
- 评分；
- 优先级；
- 所属题材/行业（有历史事实时）；
- 点击打开个股预览；
- 与次日场景和风险触发联动。

首屏关注池只显示高优先级若干项，但同卡支持“全部”展开或虚拟化列表，不能只截断后丢失访问入口。

### 3.7 窗口、日历与统计

| 现有内容 | 新位置 | 展示方式 |
| --- | --- | --- |
| 5/10/20 日窗口信号 | 多日信号矩阵 | 三列同时可见；当前选择作为全页窗口 |
| 热度、广度、接力、风险的首值/末值/变化/箭头 | 多日信号矩阵 | 全量显示，不只保留方向文字 |
| 主线、升温、降温题材 | 信号矩阵展开区 | 当前旧组件未完全展示，统一页补齐 |
| 机构信号和行业资金信号 | 信号矩阵展开区 | 保留原始方向、置信度和覆盖 |
| 30 日交易日历与每日热度 | 顶部日历弹层 | 日期联动全页 |
| 热度、涨停数、封板率、连板高度统计 | 多日矩阵下方 | 每项保留均值、最高、最低 |
| 有效交易日、风险日 | 多日矩阵标题区 | 明确显示 |

### 3.8 数据质量、覆盖和完整表

统一看板必须提供“数据质量与血缘”页签，完整显示：

- catalog 总交易日、完整、仅数据、降级和失败数量；
- 题材、行业资金、机构和窗口覆盖天数；
- canonical、derived、presentation 字段数量；
- 每个 derived 字段的可用状态、输入和缺失输入；
- SourceManager 来源状态、新鲜/复用、记录数和错误；
- Market Facts 分区、行数、覆盖率、质量等级和指纹；
- review、multiday、catalog 的 schema 版本和生成时间；
- reconciliation 状态、缺口和 warnings/errors；
- `market_overview`、`market_breadth`、`market_liquidity`、`limit_summary`、`limit_ladder`、`limit_stocks`、`promotion_stats`、`premium_stats`、`theme_snapshot`、`theme_rankings`、`theme_history`、`theme_stocks`、`sentiment_state`、`risk_signals`、`participation`、`sector_fund_flow`、`sector_rotation`、`screening_candidates`、`trend_history`、`trend_pool` 等完整数据表入口。

完整表采用同页数据集选择器、列筛选、排序、导出和虚拟滚动。没有数据时区分“来源缺失”“未发布”“无记录”，不显示伪零值。

### 3.9 紧凑态与全部展开态

同一个 `/quantx` 页面支持两种排版状态，但不拆分成两个产品页面：

- `紧凑`：首屏看板 + 每个领域一张主图 + 同页深度页签；适合日常决策。
- `全部展开`：依次渲染所有完整图、矩阵和数据表摘要；适合核对、长截图和研究。

两种状态使用完全相同的数据和日期，不形成第二套查询或业务逻辑。用户选择持久化在本地偏好中。

## 4. 交互契约

1. 日期是全页唯一主状态。`/quantx` 解析并展示最新已发布交易日，`/quantx/:date` 展示指定日期；两条路由渲染同一个组件，以兼容现有书签。窗口、视图和活动页签使用查询参数，例如 `?window=10&view=compact&tab=market`。
2. 5/10/20 日窗口是次级全局状态，进入所有多日查询键。
3. 点击题材或行业后，排行、成分股、龙头、资金、连续性和机会雷达同步筛选。
4. 点击个股复用现有 `StockPreviewDialog`，不创建第二套个股详情。
5. 一级/二级行业切换只影响行业组件，不清空当前交易日和窗口。
6. 刷新期间保留上一份有效快照，并显示 `refreshing/stale/degraded`，不闪为空页。
7. 颜色不是唯一状态表达；涨跌、风险和质量同时显示文字或图标。

## 5. 数据与前端调用链

```text
交易日参数
  -> QuantX catalog 确认可用日期
  -> review V2 获取当日权威事实与 ViewBuilder 展示结构
  -> multiday 获取截至该日的 5/10/20 日窗口结果
  -> 页面容器统一组合
  -> 各看板组件只接收稳定 ViewModel
```

历史日期严禁读取概念分析页面的“当前实时快照”。题材、行业和个股钻取必须使用截至所选交易日的 Market Facts 或版本化 QuantX View；缺少历史成员或指标时显示覆盖率，不得回填未来数据。

## 7. 分批实施

### 阶段 A：建立零丢失基线

- 为所有现有图表、字段和多日组件建立 consumer inventory；
- 增加测试，证明 review V2 和 multiday 每个字段都有明确消费者或质量页入口；
- 保存当前页面的 Playwright 全页截图和关键组件快照作为迁移基线。

### 阶段 B：统一壳层与布局

- 建立统一路由、日期选择和 16 列看板布局；

### 阶段 C：主从分析与图表收口

### 阶段 D：历史事实补齐

- 检查 console、失败网络、loading、empty、error、stale 和 degraded。

## 8. 验收标准

- `/quantx` 一页覆盖当前驾驶舱和单日富图表的全部可用能力；
- 顶部日期切换后，所有组件使用同一个交易日；
- 首屏在 1440×900 下可见指标带、市场脉搏、题材主线和今日决断；
- 默认完整页面目标控制在约 2–3 屏，而不是当前约 7,500px 的报告长页；
- 原有 12 类富图表仍可在同页深度区域访问；
- 所有 review V2、multiday、observability 和完整数据表字段都有消费者映射；
- `ladder_grid`、`ladder_detail`、窗口题材升降温、`core_stocks` 和 `institution_continuity` 不再只存在于 API；
- 紧凑态和全部展开态的信息总量一致，只改变同时展开的程度；
- 历史日期没有未来数据污染；
- 页面切换无控制台错误和失败请求；
- 前端构建、QuantX API 测试和 standalone Playwright 回归通过。
