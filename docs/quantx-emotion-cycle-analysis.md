# 情绪周期：QuantX 现状 vs 连板网 qingxu.html

> 目的：把「情绪周期与交易日历」这块的判断逻辑讲清楚，对照 https://lianban.net/qingxu.html
> 的做法（冰点判断、同景矩阵、阶段转移），给出可落地的改造顺序。
> 文中所有 QuantX 侧数字都由 `backend/scripts/analyze_emotion_cycle.py` 现算，可复现。

---

## 0. 一句话结论

**我们不缺指标，缺的是"位置"。** 现有四个口径都能算出 0-100 的分数，但没有一个回答
"现在是这轮情绪的**第几天**、历史上同样处境的下一天会怎样"。连板网的核心不是算法更复杂，
而是把「阶段 × 连续第 k 天」当成状态去统计历史频率——这一步我们完全没有。
另外，我们**已经有一个 6 阶段字段 `phase`，但它在 2026 年 89.9% 的交易日都被兜底成"修复"**，
最近 40 个交易日里 100% 是"修复"，等于已经死了。

## 1. 现在实际有四套情绪口径，彼此不通

| # | 名称 | 代码 | 输出 | 阈值 | 用在哪 | 主要问题 |
|---|---|---|---|---|---|---|
| 1 | 情绪三件套 | `app/services/emotion_state.py` | 3 个 0-100 分 + 5 档 zone | `<30 冰点 / <40 偏冷 / <60 正常 / <70 偏热 / ≥70 过热` | 复盘页结论、情绪趋势图（20 日）、交易日历（60 日格子） | 明细表只有 134 天（2026-04-27 起），做不了任何跨年统计 |
| 2 | 退潮 / 崩塌 / 参与度 | 同上 `_calc_ebb_risk_check`、`_calc_crash_signals` | 未见退潮/预警/确认、3 个 crash 信号、参与/不参与 | 绝对家数（炸板>40=蔓延等） | 复盘 s1/s2 | **绝对计数随市场规模漂移**，大涨停日会误报（见 1.3） |
| 3 | Regime 5 档 | `app/services/regime_builder.py` | `strong/lean_strong/range/lean_weak/weak` | 70 / 55 / 45 / 30 | **状态转移矩阵**、异常交易日历、回测环境过滤 | 只是分数分段，没有"阶段"语义；无持续性概念 |
| 4 | 连板梯队 6 阶段 | `app/services/market_phase.py` | `ice/ignite/rally/climax/ebb/repair` | 见 2.1 | 仅 `/regime` 页的分段展示 | **已退化**，2026 年 89.9% 是 repair |

### 1.1 三件套的公式（现在真正驱动复盘结论的那套）

**短线情绪**（打板情绪，6 项子分加权，综合后绕 50 拉伸 ×1.7）：

| 子项 | 权重 | 锚点（输入 → 分） |
|---|---|---|
| 涨停数 | 0.30 | 0→5, 48→15, 66→35, 90→50, 112→65, 142→85, 160→95 |
| 封板率 | 0.25 | 40→5, 58→15, 68→35, 75→50, 81→65, 84→85, 90→95 |
| 跌停数 | 0.15 | 0→90, 5→75, 11.5→60, 21.75→50, 39.35→35, 60→15, 100→5（越高分越低） |
| 上涨占比 | 0.15 | 0→5, 8→15, 12→35, 15→50, 19→65, 24→85, 32→95 |
| 溢价率 | 0.10 | −3→5 … 6→95 |
| 最高板 | 0.05 | 1→10, 3→30, 4→50, 5→70, 6→85, 8→95 |

**趋势情绪**（4 项，拉伸 ×1.3）：上涨占比 0.40、上证涨幅 0.30、量比 0.15、主力净流入 0.15。
**市场热度** = 短线 ×0.5 + 趋势 ×0.5（不再拉伸）。

三个分数各自落 zone，`zone` 是**静态**标签——它说明"今天有多热"，不说明"这轮走到哪"。
2026-11-27 就是三件套全 100（过热）的一天，但它在周期里的位置是"启动/主升"还是"高潮末期"，
现有字段回答不了。

### 1.2 退潮判定（4 信号 + 5 日趋势）

`relay`（晋级坍塌）、`seal`（封板率跌破 65%）、`ladder`（高度掉档）、`loss`（亏钱效应蔓延），
每个信号都同时看绝对值和 5 日变化，最终给 `未见退潮 / 退潮预警 / 退潮确认`。
这套逻辑本身是对的（"从高位回落"比"低位死寂"更像退潮），但它**只输出一个 verdict，
不进任何状态机**，也无法和历史同处境做对照。

### 1.3 一个当场可验证的误报

2026-11-27（`market_state_daily`：涨停 417 家、上涨 5381 家 / 下跌 182 家、跌停 0 家、
封板率 90.8%）的字段是：

```
market_heat_score = 100.0      crash_triggered = True
loss_severity     = "蔓延"     ebb_signal_count = 0
```

原因在 `_calc_loss_effect` / `_calc_crash_signals`：`炸板 > 40` 直接判"蔓延"、`炸板 > 30`
直接触发 crash 信号，**不看炸板率**。当天炸板 66 家（regime 口径）看着不少，但
炸板率 = 66/(429+66) ≈ 13%，属于健康水平；而 30 家的门槛在 400+ 涨停的日子里
等于只要 7% 炸板率就会触发。这类绝对阈值在大涨停日必然误报，会直接污染"冰点/退潮"的判断。

## 2. 现网 6 阶段（phase）为什么死了

### 2.1 现有判定（`market_phase.py`）

阈值标定自 2020-08~2026-08 的 p10/p60/p90，按优先级 高潮 > 主升 > 冰点 > 退潮 > 启动 判定，
其余一律 `repair`；驱动量先做 EMA（α=1/3，≈5 日）平滑，且切换需连续 2 日同标签：

| 阶段 | 规则（简化） |
|---|---|
| 高潮 | 二板以上 ≥50 或 首板 ≥220 |
| 主升 | 高度≥7 且 二板≥15 且 晋级率≥0.23；或 晋级率≥0.30 且 二板≥12 且 高度≥5 |
| 冰点 | 高度≤4 且 二板≤6 且 首板≤24（三者同时） |
| 退潮 | 5日前曾高位 且 晋级率≤0.15 且 二板回落；或 晋级率≤0.13 且 封板率≤0.57 |
| 启动 | 二板较5日前 +3 且 ≥8 且 晋级率≥0.20；或 高度抬升 且 ≥5 |
| 修复 | 以上都不满足 |

### 2.2 实测退化程度（regime_history 2892 天）

按年份 repair 占比：2015 **56.6%** → 2018 72.0% → 2022 80.6% → 2026 **89.9%**；
最近 40 个交易日（2026-09-28 → 11-27）**全部是 repair**，包括 11-27（429 家涨停、score 86）。

四个叠加原因：

1. **固定阈值随市场漂移**：2026 年涨停家数整体上移，`首板≤24` 的冰点几乎不再出现，
   而 `首板≥220` 的高潮又要求 EMA 之后仍 ≥220——EMA 把单日 399 的首板削成 ~170，两条都打不中。
2. **EMA + 2 日确认削峰**：α=1/3 意味着单日脉冲只贡献 1/3，2026 年这种"一天 429 家涨停"的
   结构变化完全被平滑掉。
3. **state 否决**：主升/高潮/启动在 `state ∈ {weak, lean_weak}` 时被强制改成 repair。
   2026 年 weak+lean_weak 占 **45.4%**（73+26 / 218），否决面将近一半。
4. **repair 是兜底**：它不是"冰点之后的反抽"这个语义，而是"没命中任何规则"。

> 结论：这个字段现在既不能用于展示，也不能用于统计。要么修，要么删——挂着比没有更糟。

## 3. 连板网 qingxu.html 的做法（拆解其口径说明）

### 3.1 六阶段 + 单一温度

阶段：**修复 / 升温 / 高潮 / 降温 / 退潮 / 冰点**，明确声明"阶段可重复或跳转，不必依次轮转"。
温度：单一 0-100 读数，当日 100° 对应高潮期。柱高=温度、柱色=阶段，近 120 日历史带。

### 3.2 历史同景矩阵（核心，我们完全没有）

- **同景定义**："同一阶段的连续第 k 天"。冰点期分 第1天 / 二冰 / 三冰 / 四冰+；高潮期分 第1/2/3/≥4天。
- **统计字段**：样本数、次日上证均值、次日上涨率、后 3 日累计、次日温度 Δ、次日去向 top2。
- **牛熊分层**：按信号日上证收盘相对 250 日年线分组（年线上 572 天 / 年线下 446 天）。
- **样本 <3 不显示**。

它的冰点数据（样本期 2022-08-26 起 1018 个交易日）：

| 同景 | 样本 | 次日上证 | 上涨率 | 后3日 | Δ温度 | 次日去向 |
|---|---|---|---|---|---|---|
| 冰点第1天 | 124 | +0.03% | 54% | +0.15% | **+26.4°** | 修复55% / 冰点25% |
| 二冰 | 32 | +0.26% | 46% | +0.32% | **+31.5°** | 修复50% / 高潮21% |
| 三冰 | 6 | +0.04% | 50% | −0.76% | **+31.8°** | 冰点50% / 修复33% |
| 四冰+ | 5 | +0.10% | 40% | +2.79% | +26.8° | 冰点60% / 高潮20% |

高潮期：第1天 96 次 +0.12%/54%，第2天 +0.22%，第3天 +0.56%，**≥4天 10 次 −0.66%/40%、Δ温度 −35.5°**。

关键洞察：**冰点之后的温度反弹幅度（+26~32°）远大于其他任何阶段**；而高潮持续到第 4 天开始
转为负期望。这两条都不是"分数高低"能表达的，必须靠 k-day 计数。

### 3.3 阶段转移矩阵（6×6）

行=今日、列=次日，纯历史频率。它的矩阵有两个特点值得学：
- 冰点行 → 修复 53%（最高），退潮行 → 修复 34%，说明"退潮之后先修复"是主路径；
- 高潮行 → 高潮 36% / 降温 33%（自我延续强），而**升温行 → 降温 29% / 退潮 28%**（升温和退潮只隔一天）。

### 3.4 阶段持续天数

修复 195 段/平均 1.2 天/最长 3 天/占比 22%；冰点 124 段/1.4/6/17%；高潮 96 段/1.6/8/15%。
这段信息直接告诉读者"当前阶段还剩几天"的经验分布。

### 3.5 分阶段晋级率（这条最反直觉）

| 信号日阶段 | 次日 1进2 | 次日 2进3 |
|---|---|---|
| 冰点期 | **18.5%** | 34.7% |
| 高潮期 | 18.2% | 32.3% |
| 升温期 | 16.4% | 33.1% |
| 修复期 | 15.3% | **35.7%** |

**冰点期打首板的次日晋级率最高（18.5%），修复期最低（15.3%）**——与"冰点别打板"的直觉相反。
我们现在的 `promotion_funnel` 只有全样本基线，没有按阶段切分，所以拿不到这条结论。

### 3.6 值得抄的三件事

1. **k-day 计数**：把"连续第几天"作为状态的一部分，这是同景矩阵的前提。
2. **牛熊分层**：同一个形态在年线上/下含义不同，分组后样本更小但更同质（并明确标注样本数）。
3. **口径透明**：样本期、样本数、<3 不显示、历史频率≠预测——全部写在页面上。

## 4. 用我们自己的数据回算（可复现）

脚本：`backend/scripts/analyze_emotion_cycle.py`（读 `regime_history` 2892 天 + 上证 250 日年线）。

**温度**：复用三件套"短线情绪"的锚点与权重（去掉无数据的溢价项），拉伸 ×1.7。
**阶段**：温度在**滚动 250 日分位**中的位置 + 3 日温度变化方向——用滚动分位替代固定阈值，
这是为了从根上解决 2.2 的漂移问题。

### 4.1 分布与持续（vs 连板网）

| 阶段 | 我们 天数/占比 | 段数/平均/最长 | 连板网 占比/平均/最长 |
|---|---|---|---|
| 冰点 | 342 / 11.8% | 290 / 1.2 / 3 | 17% / 1.4 / 6 |
| 修复 | 308 / 10.7% | 265 / 1.2 / 3 | 22% / 1.2 / 3 |
| 升温 | 642 / 22.2% | 485 / 1.3 / 6 | 8% / 1.1 / 4 |
| 主升 | 309 / 10.7% | 256 / 1.2 / 4 | —（它叫升温/高潮） |
| 高潮 | 582 / 20.1% | 392 / 1.5 / 7 | 15% / 1.6 / **8** |
| 退潮 | 709 / 24.5% | 525 / 1.4 / 6 | 24% / 1.5 / 6 |

高潮的"平均 1.5 天 / 最长 7 天"与它的 1.6/8 几乎一致，说明温度口径和阶段切分方向是对的；
偏差在**升温偏多（22% vs 8%）、修复偏少（11% vs 22%）**——我们把"反抽第一天"也标成了升温，
需要把"从低位回升但尚未确认"单独归入修复。这是标定问题，不是结构问题。

### 4.2 同景矩阵（我们自己的历史）

| 同景 | 样本 | 次日上证 | 上涨率 | 后3日 | Δ温度 | 次日去向 |
|---|---|---|---|---|---|---|
| 冰点第1天 | 290 | +0.04% | 58% | +0.15% | **+23.7°** | 退潮27% / 升温22% |
| 二冰 | 43 | **+0.23%** | 53% | **+0.54%** | +21.8° | 退潮28% / 升温21% |
| 三冰 | 8 | +0.01% | 62% | −0.12% | +18.8° | 修复75% / 升温12% |
| 高潮第1天 | 391 | +0.04% | 52% | −0.01% | **−17.2°** | 高潮30% / 退潮24% |
| 高潮≥4天 | 18 | −0.28% | 56% | **−0.69%** | −18.6° | 主升39% / 退潮33% |
| 退潮第1天 | 524 | +0.03% | 53% | +0.02% | +9.4° | 升温28% / 退潮26% |
| 升温第1天 | 485 | −0.06% | 49% | −0.05% | −7.4° | 退潮28% / 升温22% |

与连板网的结论方向一致：
- **冰点/二冰之后温度平均反弹 20°+**（它们 +26~32°，我们 +21~24°，口径不同但同向）；
- **二冰的次日收益好于冰点第 1 天**（+0.23% vs +0.04%，后 3 日 +0.54% vs +0.15%）；
- **高潮持续 ≥4 天后 3 日为负**（−0.69%），与它的 −0.51% 一致；
- 我们的"升温第 1 天"次日为负（−0.06%、Δ温度 −7.4°）——这正是 4.1 里升温归类的副作用，
  修掉归类后应该会转正。

牛熊分层（冰点期）：年线上方 n=136 次日 +0.03%/57%，年线下方 n=183 +0.11%/58%，
我们这版差别不大；它的冰点也是两组接近（+0.12%/54%）。说明**牛熊分层对冰点的增益有限，
真正有用的是 k-day**——优先级可以往后放。

## 5. 差距对照

| 维度 | QuantX 现状 | 连板网 | 差距性质 |
|---|---|---|---|
| 状态定义 | 3 个分数 + 5 档 state + 6 阶段 phase（已死） | 6 阶段 + 单一温度 | 需要统一，不需要新增指标 |
| 连续第 k 天 | 无 | 核心，二冰/三冰 | **结构性缺失** |
| 同景统计 | 无 | 有（含牛熊分层、样本数） | **结构性缺失** |
| 转移矩阵 | 5×5，用 regime state，500日/全史切换 | 6×6，用阶段 | 口径错位（不是阶段） |
| 阶段持续天数 | 无 | 有 | 易补 |
| 分阶段晋级率 | 只有全样本基线 | 有 | 易补（数据已具备） |
| 阈值稳定性 | 固定阈值（已漂移） | 未公开，但阶段分布稳定 | 需改滚动分位 |
| 绝对量 vs 比率 | 炸板>40、跌停>20 等绝对数 | 以高度/宽度/晋级率为主 | 需比率化 |
| 口径透明 | 部分（zone 阈值未标） | 样本期/样本数全标 | 易补 |

## 6. 建议的落地顺序

### P0（先修正确性，不改展示）

1. **修 `crash` / `loss_severity` 的绝对阈值**：炸板改炸板率（`broken/(broken+limit_up)`），
   跌停改"跌停/涨停比"，下跌家数改下跌占比；并加"大涨停日不判亏钱蔓延"的护栏。
   现有 2026-11-27 这种误报会让整块情绪判断失去可信度。
2. **重做 `phase`**（`market_phase.py`）：
   - 温度改成**滚动 250 日分位**驱动，去掉固定绝对阈值；
   - 保留 EMA 但降低强度（α=0.5 或只对 k-day 计数用平滑，不用平滑后的值判阶段）；
   - 去掉 `state` 硬否决，改成"负面环境下降档一级"（主升→升温）而不是直接归 repair；
   - `repair` 不再兜底：显式定义"低位回升但未确认"= 修复，"其余"用最近一次阶段延续（滞后判定）；
   - 目标分布（对齐连板网量级）：修复 20~25%、退潮 20~25%、高潮 13~17%、冰点 14~18%、升温 8~12%、主升 8~12%。
3. **`phase` 落库 + 回标全历史**（`refresh_phase_labels` 已有钩子），并在 `market_state_daily` 里同步一份，
   让复盘页只依赖一张表。

### P1（补结构性能力）

4. **新增「情绪同景」卡片**（替换/扩充现在那个 5×5 矩阵）：
   - 状态 = `阶段 × 连续第 k 天`（k=1,2,3,≥4）；
   - 字段 = 样本数 / 次日上证均值 / 上涨率 / 后 3 日 / Δ温度 / 次日去向 top2；
   - 用 `regime_history` 现算（2892 天，够用；不必等新数据积累）；
   - 样本 <3 不显示；牛熊分层做成可选开关（数据已在手，但增益有限）。
5. **转移矩阵换成 6 阶段**，5 档 state 矩阵保留为"环境档"对照（两者语义不同，别混）。
6. **阶段持续天数卡**（段数/平均/最长/占比），以及**分阶段晋级率**（把 `phase` join 到
   `promotion_funnel` 的 ladder 上，按信号日阶段分组）。
7. **情绪日历升级**：格子按阶段着色（6 色 + 温度深浅），当前日期标 `冰点·二冰` 这样的
   `阶段·第k天`；点格子跳当日复盘。

### P2（口径统一，可选）

8. 三件套（短线/趋势/热度）与"温度"合并成一个对外口径：对外只讲"温度 + 阶段"，
   三件套作为温度的内部拆解（展开可见）。现在复盘页同时暴露 3 个分数 + 5 档 zone + 5 档 state，
   读者不知道该信哪个。

## 7. 数据口径备注（顺手记一下）

- 同一个名字 `up_ratio` 在两张表里含义不同：`regime_history.up_ratio` 是**涨跌家数比**
  （2026-11-26 为 0.4902），`multiday.calendar[].up_ratio` 是**上涨占比百分数**（同日 96.5）。
  `market_state_daily` 里叫 `up_ratio_pct`，是对的。跨表取数时极易踩错，建议统一成
  `up_ratio_pct`（百分数）与 `up_down_ratio`（比值）两个名字。
- `market_state_daily` 与 `regime_history` 同一天的涨停数会出现差异（2026-11-27：417 vs 429），
  两条采集链路不同步；做阶段判定时需固定用一条，否则同一天会出现两个温度。
