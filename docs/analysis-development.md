## QuantX 四维市场风险画像

单日 `sections.s2.risk_radar` 是 `risk-radar-v3` 确定性 ViewBuilder 结果，不调用大模型，也不新增可供策略使用的市场事实。输入依次为已发布的 `market_breadth_daily`、`market_state_daily`、`market_liquidity_daily`、`limit_ladder_daily`、`limit_event_daily`，以及 `KlineRepository` 中的指数日 K。连板事件总账中有高度、但梯队事实漏记的涨停股按代码去重后补进梯队计数。五日成交基线取目标日前五个已发布交易日，不包含目标日。

四维顺序固定为广度与尾部、接力与封板、量能与承接、指数与趋势。连板高度和 3/4 板缺档归入接力维度。每维返回 `tone=red|amber|green|null`、状态、全部已核对的当前数值和来源；逐项数值带独立 `tone`，触发红／橙条件时还带 `judgement`。脚本将每个触发条件的具体判断按维度汇入完整 `summary`；页面标题区展示简短 `headline`，逐项判断由异常数值的悬停／键盘焦点说明承载，基准和样本量保持中性。红色表示当日显著风险，橙色表示需要关注，绿色表示正常。`null` 仅表示关键输入缺失；四情绪不齐也单独提示待同步。顶部标题按“数据缺失 → 广度与接力双红 → 广度与接力正常但量能偏弱 → 其他红色 → 其他橙色 → 全绿但单项提示 → 全绿且无提示”的固定优先级生成，不调用大模型。前日变化只写进证据，不改变维度颜色语义。

当前维度阈值：广度下跌占比达到 80%、跌停达到 50 家，或下跌占比达到 70% 且跌停达到 30 家为红；下跌占比达到 55% 或跌停达到 15 家为橙。接力溢价不高于 −1% 且晋级率低于 20% 为红；溢价为负、晋级率低于 25%、封板率低于 75%、最高板不足 4 板，或最高板达到 4 板但 3/4 板任一缺档为橙。成交额低于前五日均额 70% 且下跌占比达到 70% 为红；成交额低于均额 90% 或高于 140% 为橙。普通指数全部低于各自 MA10、四情绪也全部低于 MA10 且全 A 当日跌幅达到 3% 为红；普通指数站上 MA10 不超过 2 条，或四情绪站上 MA10 不超过 1 条为橙。单项数值另按自身阈值提示：成交额低于前五日均额 80% 或高于 150%、较前日绝对变动达到 15%、普通指数或四情绪全部低于 MA10，以及四情绪触及各自高低位阈值均标红；单项颜色不提升维度整体等级。维度仅有一项轻微橙色且无红项时，可标绿并写明“基本正常”：广度需同时满足下跌占比低于 70%、跌停少于 20 家、深跌占比低于 3%；接力需最高板至少 4 板且 3/4 板无缺档、溢价不低于 −0.5%、晋级率不低于 22%、封板率不低于 70%；量能需处于前五日均额的 85%～145%。指数与趋势不使用此宽限，单项橙色及其判断仍保留。这些是风险提示阈值，不是仓位或交易建议。

广度行展示上涨、下跌、下跌占比、跌停、上涨股平均涨幅、下跌股平均跌幅和跌幅严格超过 7% 的个股占比；平盘与未知家数不在此行重复展示。深跌占比达到 2% 为橙、达到 5% 为红，平均涨跌幅只提供分布背景。深跌占比分母是当日涨跌幅有效的股票数，来源为 `market_breadth_daily` v3；旧事实缺少逐股幅度时不推测均值或深跌比例。

通达信 `880699.SH`、`880880.SH`、`880823.SH`、`880003.SH` 由日常指数同步通过 TDX Provider 定向采集，并进入 `kline_index_daily` 与 `kline_index_enriched`。页面请求只读本地已发布 K 线。四条线的偏离率为 `(当日收盘价 / 最近 10 个交易日收盘均值 − 1) × 100%`；高／低位阈值分别是 `+4.7/−4.0`、`+8.3/−5.9`、`+3.9/−4.0`、`+4.7/−4.0`（单位：百分数值）。四情绪与普通指数分别展示，不合成总分；四指数原始编制方法不在本规则定义范围内。

## 板块活跃参与与股票池参考

市场实验室 → 板块资金 → 表现与活跃，与股票池题材详情共享 `/api/amv/sectors` 和 `/api/amv/analyze`。自定义这两个页面通过 `load_ths_memberships` 仅读取 `ext_gn_ths` / `ext_hy_ths` 完整成分快照；保留 `AI PC`、`WiFi 6`、`DRG/DIP` 等名称中的空格与斜杠。概念、风格/股权属性分维保留，行业按一级/二级拆分。QuantX 和内置行业/概念页继续使用原有分类路由。

板块压力的 `sector-flow` / `sector-radar` 接口默认 `taxonomy=ths`，行业取THS二级行业、概念取研究概念，共用上述完整成分；`sector-members` 只按该分类精确下钻，不用其他来源的同名行业推断成员。多概念成分的日收益必须按证券与概念同时分组递推，不能在展开后的重复证券行间错位。`taxonomy=source` 为独立外部资金观察，来源缺该分类时不回退成THS；该视图不提供THS成分下钻。OHLCV压力不是主力净流入。宏观离散度也读取THS二级行业。

股票池题材参考前端只提交板块名、分类与日期，不传入池成员；入池名单变化不影响板块计算范围。动态题材没有同名映射时，用户可选择THS概念或行业作研究参照；页面区分原题材与参照，不推断两者成分相同。该指标只用于研究观察，不改变入池过滤或评分。动态题材使用完整术语匹配和已核实别名，禁止包含关系、相似度和括号内片段自动并组；复合术语不得按第一个关键词吞并其他题材。英文缩写必须避免单词内部匹配（如Micro不能命中CRO）。可选模型归一化也须遵守确定性别名约束，不得随意改类或删除合格题材。规则版本为 `exact_term,explicit_alias,shared>=2,noise=v4`；历史首次快照不重写，跨规则变化标记不可比。

纯计算模块 `active_market_value.py` 每只股票计算一次：`q=成交额/(不复权收盘价×普通流通股本)`，`u=1-exp(-KF×q)`，`a_t=u_t+2^(-1/H)×(1-u_t)×a_(t-1)`，`V=M×a^γ`。默认 H=8、γ=1、KF=1.15；KF调整输入换手率。板块先逐股递推，再累加活跃市值与流通市值，占比为两者之比，不能直接对板块总成交额递推。原通达信使用自由流通股本；本项目普通流通口径属于研究估计。

列表默认按近5交易日占比变化排序（百分点），另可按活跃占比、扩散率排序。扩散率为占比近5日上升的可比成员比例。详情显示日/5日变化、前三集中度、成员读数及30日曲线；活跃参考指数与固定成员等权价格以首日为100，实际占比使用独立百分比轴。红增绿减表示方向；活跃增加可能伴随抛压，不等同净流入或买入信号。

服务限定读取目标日前650自然日作为预热范围，实际递推与比较按交易日。缺日/无效输入重置状态，真实零成交额正常衰减；最近30交易日采用相同成熟成员集合。可比成员数、映射缺失和市值覆盖分别披露；任一成分缺少目标日市值时，市值覆盖返回 null，不能补零。250日分位只在连续成熟数据足够时返回。最新成分快照回看、重建历史股本与最新股本代理均保留来源说明，不作为已验证历史PIT。

Service 使用最多两份日期批次的5分钟进程缓存，各分类和详情复用逐股递推；失效键包含 Repository、目标日期、已发布日线 generation、成分内容、证券信息和历史股本内容。冷请求串行合并，读取期间 generation 变化则返回可重试错误；列表与详情均不调用供应商、不新增事实分区。前端 query key 包含日期、范围与分类，缓存5分钟。

## 市场实验室新增研究视图与复盘统计

`GET /api/market-lab/sector-research?dimension=industry_level1|industry_level2&horizon=1|3|5|10&as_of=`共用THS完整行业成分和本地复权日K批次，提供资金—宽度联合相图和行业后续收益。相图横轴明确为收盘位置×成交额的5日标准化压力（不是主力净流入），纵轴为MA20宽度5日变化（百分点）；气泡为当日成交额，箭头为昨日坐标。宽度窗口和收益要求实际相邻交易日，压力5日窗口及宽度两端有效成员不足80%时返回null。相图同时披露当前宽度与有效成员数。

行业后续结果按完整交易日窗口复合成员等权复权收益，并比较同期全市场等权收益；最新成分回看属于`latest_ths_snapshot_proxy`，不是历史PIT或交易回测。矩阵按观察日宽度20个百分点分组和5日扩散/收缩分组，先对同日样本平均再按日期等权；行业表只统计与当前行业当前宽度档、扩散方向相同的历史状态。未成熟和行情缺失分别计数，返回样本数与不同日期数。服务只读Repository，以日线generation、完整成分内容、日期、层级缓存两份批次5分钟；页面不触发外部采集。

`GET /api/market-lab/concept-overlap?sector=&limit=10`读取完整THS概念成分，返回共同成员、Jaccard、双向覆盖比例和共同证券代码。默认以所选概念的前10关联展示邻接网络与表格，不自动合并或修改题材归类；网络位置不表达产业或因果关系。

ETF表格默认按20日普通对数回归年化收益×R²降序；40/30/20/10%的1/5/20/50日加权涨幅作为独立列保留。表头支持升序、降序、恢复默认；排名变化以今天同一名单及当前排序指标的昨日数值计算，动量变化为当前排序指标的数值变化。`etf-momentum`兼容新增`symbols`逗号分隔标准代码查询，提供成交额前60与浏览器保存的自选名单；返回`previous_metrics`、实际请求与排除数，旧字段继续保留。最新日线不齐的ETF不混入目标日排名。

股票池review的`attribution.combinations`按完整来源集合互斥分组（至少两路），与原九路重叠来源、新增来源、迁移和研究材料统计共存。各组新增上涨比例、有效行情日期、期间最低变化均值及其样本数；最低变化相对次日开盘，不能标为峰谷最大回撤。前端“入池理由与后续表现”不造评分段或预测概率，周期共享现有1/3/5日选择，首次冻结与回放状态继续按原规则判定。

风险画像历史检验仅由`scripts/analyze_market_signal_efficacy.py`复用正式`_build_risk_radar`离线重算，输出到`data/research/market-signal-efficacy-YYYYMMDD`，不新增页面、不改事实或阈值。同时计算状态日与首次进入状态的1/3/5日中证全指结果、最低价相对观察日收盘变化，以及相对非该状态日期的均值差；采用固定seed的交易日块重采样区间，首次进入要求立即前一交易日状态已知。生成结果不是已验证交易收益。

## 1. 开始前分类

先回答：

1. 输入是否已存在于 KlineRepository、MarketFactRepository 或 ext_data？
2. 输出是可复用事实、确定性派生指标，还是仅展示状态？
3. 时间窗口按交易日还是自然日？
4. 数值单位、复权口径、时区、空值和质量等级是什么？
5. 是否会被策略、回测、监控或多个页面复用？

若分析结果需要叠加到个股 K 线，不得在 React 页面或 ECharts option 中直接复制业务算法。纯观察、不可执行的结构标记可实现 `ChartLayerProvider`，消费 `/api/kline/chart` 的最终同口径 candles，返回版本化 `ChartAnnotationLayer`；必须提供稳定 ID、算法版本、输入指纹、确认时间、证据和数据不足状态。凡是会被解释为候选、入场、离场或交易触发的条件，必须先注册为正式策略，不得用独立 `pattern.*` 图层绕过策略注册。

正式策略在 K 线中有两条清晰分开的路径：策略面板、回测或实时监控产生的跨日证据写入 `strategy_signal_events`，供“已记录事件”图层读取；已声明 `META["chart_preview"]={"enabled": True, "mode": "single_asset"}` 的 `matrix_native` 策略可由 `POST /api/strategies/preview` 对当前单一标的、所选日线区间和必要预热 K 线做因果信号回放，返回临时 `ChartAnnotationLayer`。预览不得执行全市场扫描、不得写入事件仓库、不得模拟成交，也不得计算单标的横向评分；不支持该契约或周期的策略必须明确不可用。`signal_kind` 用于区分策略信号、回测成交和实时触发。

输入不存在时先走 `data-foundation.md`，不要从页面或 service 临时抓取供应商接口。

Quants 迁移策略使用稳定 ID 与真实形态名称，当前按核心语义验收，见[策略核心迁移验收](spec/quants-strategy-core-acceptance-20260905.md)。`quants_growth_trend_legacy_v1` 仅保留兼容读取，使用 `research_only` 排除默认列表；不应将其描述为原版 V2 的完全复刻。迁移策略只计算已完成日 K。回调低吸的 `watch` 是观察候选，不能映射为自动买入；缺少真实 `net_mf_amount`（万元）时必须明确不可计算，不得以价量估算替代资金流。

## 2. 标准开发链

```text
Repository 输入
→ 纯计算函数/领域 Service
→ API 响应模型
→ frontend api.ts 类型
→ queryKeys
→ page/component
→ 单元、API、构建和 Playwright 验证
```

### 2.1 Repository

Repository 只负责范围读取、来源优先级和稳定结构。读取时限制日期和列，避免全表扫描。不要把图表颜色、文案或排序标签放进 Repository。

### 2.2 计算逻辑

优先写纯函数：显式输入、显式窗口、确定输出。Polars 计算优先表达式和批处理。

必须测试：

- 最小窗口；
- 正常窗口；
- 非交易日和缺日；
- null、空表和备用来源；
- 排序稳定性；
- 禁止未来数据。

### 2.3 Service

Service 组合 Repository 和纯计算函数，负责业务选择、缓存与错误状态。不要让 Service import scraper、React 展示类型或任意本地报告文件。

### 2.4 API

API handler 保持薄层：校验参数、调用 Service、映射响应。新增响应字段同步更新 `frontend/src/lib/api.ts`；错误应使用可操作状态，不返回模糊 500。

### 2.5 前端

- 请求统一定义在 `api.ts`。
- query key 统一定义在 `queryKeys.ts`，影响结果的日期、周期和维度必须进入 key。
- 页面组合状态和区域，重复图表逻辑下沉组件。
- 保留上一份有效数据直至刷新完成。
- 明确 loading、empty、error、disabled、stale 和 degraded。
- A 股颜色和单位必须与现有页面一致。

股票池是与QuantX平级的确定性派生面板。`app.stock_pools`只能读取`KlineRepository`、`MarketFactRepository`和通用Research索引，按交易日向`data/stock_pools/date=YYYY-MM-DD/`原子发布`summary.json`、`candidates.json`、`details.json`及manifest；API和React页面不得读取研究账本、QuantX展示JSON、外部项目目录或导入`legacy_scrapers`。正式路由为`/stock-pools`，数据接口为`GET /api/stock-pools`、`GET /api/stock-pools/{date}`、候选列表、候选详情及`POST /api/stock-pools/runs`。盘后自动任务和`POST /api/pipeline/run`都必须在QuantX事实发布后调用同一股票池发布器。
股票池候选的`price_context`是已发布复权日K派生的MA10/MA20距离、20日高点回撤和近10日涨幅，只作浏览辅助，不参与九路召回。Research索引的`available_at`控制历史可用性；SMNC公司关系区分标题单股、标题多股和正文提及，`match_excerpt`保留该公司附近的原文。候选的`research_count`仅计入当时可用的已审计主证据/辅助证据或SMNC标题单股材料；`research_breakdown`另列全部匹配材料中的SMNC标题单股、已审计主证据和反证数量，个股详情展示其中排序最前的三条。这些数量不作为低吸质量或收益评分。
股票池`summary.theme_contexts`从已发布`theme_observation_daily`为池内题材附加同花顺热点、问财涨停题材和DeepQ的近5个交易日榜单观察；只按当前题材名或当天逻辑术语的确定性别名精确匹配，歧义标记为`ambiguous`。来源名称包含当前题材名但更细时，另列`related_narrower`供发现线索，不把它算作当前题材上榜，也不推断个股是该细分成员。每个来源分别给出目标日榜内名次、该源前次可用榜单名次、可用天数和上榜天数；榜外、来源缺失分别标记，不跨来源合成热度分数，榜外不等于市场冷门。题材在当日逻辑层出现时标记`dated_logic`，仅来自静态概念时标记`latest_static_proxy`；低吸混合组还须提示其中含最新静态关联，不作为历史时点成分证据。`summary.theme_context_version`独立标识此派生口径。候选的`research_focus`展示目标日已可用的SMNC标题单股材料、原文摘录、可用天数、标题或摘录明确出现的当前题材词以及已有已审计反证；这些是可核对的研究线索，不新增交易逻辑题材、召回、阶段或分层。动态题材研究背景可用当日聚类原始术语在SMNC标题中作字面检索，先从标题剔除已识别的公司名，按已审计概念、题材名、原始术语和旧规则标签区分匹配口径并去重同标题材料；不用正文宽泛概念推断新题材成员。动态题材排除资金状态、财务状态和传闻澄清等非题材术语，原始逐股证据仍保留；噪声规则改变须更新`topic_normalization.rule`，同日LLM别名只能在该规则一致时复用。热点迁移比较须同时检查聚类规则、模式和提示版本；不同口径标记不可比。`daily_changes.topic_status`独立标记题材比较状态，跨规则日不生成逐股题材变化或题材变化计数。
低吸队列的“当日成组题材 / SMNC定向 / 无成组题材”只过滤当前已入池候选的浏览范围，原有阶段及距MA20排序继续适用；逐股标明题材来自当日逻辑或最新静态关联。逐股当日解读有合格术语但不足两只成组时，候选保留`unclustered_terms`作原文核对提示，不生成一两只成员的顶层题材卡；“无成组题材”因此可能包含当日解读。低吸顶层题材有当日逻辑时优先按当日逻辑成组，静态主概念仅在该股没有当日逻辑时补充成组；工作台将它与当日逻辑题材并为一个题材分类池，成员取并集去重，所选题材下的所有浏览范围均限定在该成员集合并按阶段分组。原始静态成分仍在个股详情和交叉关联中展示，阶段迁移API使用原有成员口径。SMNC标题单股材料不能单独成为召回或已验证低吸信号。17:45恢复任务只在最新enriched日期缺少可读股池快照时自动发布，避免休市日或上游未更新时重复刷新旧快照的发布时间；显式指定日期的重算不受此限制。
新发布的股票池另存`eligible.json`，仅记录同一次基础过滤合格的证券代码，供历史池外对照使用；它不是第十路召回。首次发布时在`stock_pools/first_published/date=YYYY-MM-DD/`原子留存完整快照，此后同日重算仅替换工作台所读的当前版。历史复盘优先读取首次版及其个股详情；上线前已存在且没有首次版留存的日期继续读取当前版，但明确标记为`replay`，不得称为实盘可核验样本。观察日至目标日的整条快照路径都必须有首次版且及时发布才记为`recorded`；变化归因还要求前一交易日也是按时首次版，单列`recorded_transition_count`，避免上线首日拿回放快照当作已验证的昨日状态。首次版发布时间在对应交易日北京时间15:00前标记为`early`，晚于Market Facts交易日历中下一交易日北京时间09:30标记为`late`，下一交易日尚未知时标记为`unknown`，均不算实盘可核验。工作台摘要接口返回当前版`published_at`和首次版留存状态。
Research索引的`available_at`为材料可用时点：SMNC以本地采集时间为准，已审计材料以研究发布与采集的较晚时间为准；历史股票池只能关联在目标交易日北京时间结束前已可用的材料，不能仅按材料原始发布时间回填。

股票池的基础过滤固定为总市值20—3000亿元、当日成交额不少于1亿元、换手率不少于1%并排除当日可识别ST。总市值和展示价优先使用`raw_close`，技术形态使用连续复权序列；当日涨跌幅为原始收盘价相对上一交易日原始收盘价。来源标签只表达召回理由，`primary_stage`表达当前状态，题材只聚合已召回股票。详情中的Research材料必须按目标交易日截断，页面请求不即时调用模型或供应商。
股票池`summary.exchange_coverage`记录沪、深、北交易所的上市、当日行情和基础过滤数量。发布前要求沪深各有至少500只上市股票、当日行情覆盖各自上市数的70%以上，且各有基础过滤合格股票；未通过时拒绝覆盖已有快照。`source_quality.market_universe`单独表达基础股票覆盖，不计入九路召回来源数。`instrument_generation`记录本次计算实际使用的证券名称、交易所和总股本数据摘要，与行情矩阵`input_generation`分别追溯。
阶段迁移通过只读接口`GET /api/stock-pools/{date}/evolution?mode=hot|low&topic=&window=`与`GET /api/stock-pools/{date}/candidates/{symbol}/history?window=`从已发布候选快照计算，不新增召回或候选集。热点题材按前后交易日同名当日逻辑标签比较：分别计数两日留存、昨日已在池但新入题材、昨日未入池、离开题材仍在池、今日未入池；主阶段变化由已发布来源集合与优先级产生，不表示单向行情演进。接口保留已发布迁移和未变化成员的完整流水数据；工作台主视图以当日题材成员和阶段分组为主，不重复展示逐股迁移图。趋势低吸的静态概念只圈定今日候选，历史展示今日成员在过去快照中的在池和阶段情况，不宣称历史时点概念成员。缺快照、规则版本不同或来源降级须在响应和页面显式标记；历史窗口以已有交易日快照计，不用自然日补零。
历史复盘只读接口`GET /api/stock-pools/{date}/review?window=20&horizon=1|3|5`将窗口内每日已发布候选作为独立观察样本，并按本规则版本内首次出现、再次入池、阶段变化、来源变化、题材变化和持续观察分组；变化组可重叠，股票可跨日重复出现。只有前一日快照和后续目标区间的规则版本一致、快照质量完整时才计入到期结果；未到期和不可比样本分别标识。目标日须是Market Facts交易日历中观察日后的第N个交易日；若中间交易日缺少已发布快照，结果标记不可比。离池表示目标日未在候选池，不表示退市或不可交易。留池和阶段去向来自股票池快照；复权收盘变化来自`KlineRepository.get_daily_batch`同股票观察日与目标日的`close`，离池股票仍计入行情，缺日K时收益为空且从行情统计分母排除。该变化是收盘至收盘的历史描述，不包含次日开盘可成交性、交易成本或策略收益。页面逐股下钻使用对应观察日的候选详情，避免把当前证据回填到历史。历史页按题材回看只使用观察日快照内的 `topics`，题材筛选同步限定流水、逐日样本和逐股明细；全局变化类型卡片须明确标为全局样本。
复盘统计同时返回到期、待到期、不可比观察次数与有日K次数；收益均值和中位数只对有日K的到期观察计算。页面的历史阶段流水图从同一批逐股观察聚合，分别展示“前一快照→观察日”和“观察日→目标日”的真实两点路径；后者只使用到期且可比样本。默认展示按样本数排序的主要路径，并披露已展示路径的覆盖数；点击流带或逐日样本行筛选下方逐股记录。样本日历标明历史缺口，不将不同规则版本的快照拼成连续样本。
复盘组统计另返回到期观察涉及的不同股票数，以及同日池内对照差：对每个同时具有该组和其余候选有效日K的观察日，分别计算两组复权收盘变化均值及差值，再对日期等权平均，并返回可比较日期数。对照范围仍是同一股票池，并非全市场基准；组可重叠、同股可跨日重复，不能把这个差值解释成独立策略超额收益。未来阶段属于事后结果，页面须明确标注其在观察日不可知。
复盘另返回下一交易日复权开盘价至目标收盘价的价格代理、期间相对开盘价的最高/最低变化，以及用户选择的假设往返总成本`cost_bps`扣减结果。交易日历可用时，缺少中间或已到期目标交易日股票池快照的观察标记不可比，不得继续显示为待到期；它仍未验证涨停可买、实际成交或滑点，不应称为策略收益。首次发布快照有冻结`eligible.json`时，按观察日以合格但未入池股票的同口径开盘代理均值作池外基准，再对可比日期等权平均；旧快照缺少首次版合格全集时保持空值。复盘同时按九路来源、当日新增来源、具体阶段迁移、定向研究材料和低吸材料交叉组返回重叠的描述性统计；它们不能直接解释为相互独立的因果贡献。
个股侧栏的简洁日K复用现有`/api/kline/daily`查询与缓存键，仅在打开侧栏时请求，并以所选股票池快照日期截断K线；桌面侧栏约占半屏，图表显示最近120根可用日K（上市或本地数据不足时显示实际根数），只包含蜡烛、MA5/MA10/MA20和成交量。图中为前复权价格，股票池候选的展示收盘价仍按原始价格口径。

QuantX 页面分享统一调用 `frontend/src/lib/exportStaticHtml.ts`：它从现有 QuantX API 收集一个交易日的已发布响应，内嵌页面样式和由 `frontend/src/portable/quantxPortable.tsx` 启动的 React/ECharts 便携运行时，在浏览器内生成一个不依赖后端的交互式 HTML。便携运行时只把内嵌响应映射回既有 `quantxApi` 契约，不复制指标计算或另建报告数据流水线；批量百日新高成员使用 `GET /api/quantx-data/new-high/{trade_date}/member-bundle`，避免导出时逐聚类请求。页面按钮与 `scripts/export_quantx_static.py` 必须复用这一实现；命令行脚本需使用 Edge 在断网浏览器上下文重新加载文件，验证图表重绘、悬浮提示、筛选、下钻、折叠区、本机地址和网络请求、控制台错误及页面级横向溢出。操作说明见 `docs/quantx-static-export.md`。

单日 QuantX V2 必须额外区分字段来源：可复用数值来自 Repository，页面专用摘要进入版本化 ViewBuilder，标题和布局进入前端常量。V2 从 `QuantXReviewResponseV2.empty(trade_date)` 构建，禁止深拷贝展示缓存；新增前端消费字段必须通过 `scripts/audit_quantx_review_consumers.py`，并在 schema endpoint `GET /api/quantx/review/schema/v2` 中声明来源、单位、空值和排序。默认响应的 fallback 和 implicit cache 必须始终为空。

QuantX 高级图谱由 `app.quantx_data.advanced.build_advanced_snapshot()` 在服务层一次性构建，前端只通过 `GET /api/quantx-data/advanced/{date}` 发起一个共享查询。当前契约固定包含 15 张数据卡片；每张卡必须返回 `status`、`rows`、`data`，缺数据时显式返回 `unavailable`，不得生成模拟值。固定连线但没有统计因果依据的“风险传导链”不属于当前契约。行业相关性和 RPS 轮动使用当前行业成分回看历史，主线强度历史使用当前概念成分回看历史；响应和页面必须持续展示“不是历史时点成分、越接近当前日期越可靠”的口径提示。市场状态转移矩阵来自 TickFlow Regime 四维模型，顶部市场热度、短线情绪和趋势情绪来自 QuantX `market_state_daily`，两套分值与状态不得直接互换。跨日队列存活 Sankey 和龙头交接时间轴不属于当前契约。

市场状态转移矩阵同时提供近 500 日和目标交易日之前的全部 Regime 历史，页面默认近 500 日并允许切换全历史；两种口径都必须返回首日、末日、样本交易日数和实际相邻交易日转移次数，页面不得省略统计区间。行业 RPS 轮动时钟除当前“最近 5 日 RPS 与此前 5 日 RPS 之差”外，还返回以前一交易日为截止点的坐标；页面默认只突出位移最大的 8 个行业，昨日点和箭头必须低透明度，允许切换全部或关闭轨迹。行业资金分布的流入、流出必须使用同一个总面积尺度；后端从完整行业事实返回流入总额、流出总额和净额，前端未逐项展示的长尾行业合并为“其他”但不得丢失总额。

换手—收益拥挤密度必须读取 `KlineRepository` 已按历史股本补算的 enriched `turnover_rate`（百分数值），不能直接用实时窄表中的空换手率判定整张卡不可用。成交额洛伦兹曲线除当日值外，同时返回上一交易日曲线和所选日期之前最多 20 个交易日的逐日曲线均值；对应 Gini 分别展示为当日、昨日和前 20 日均值，历史基线不包含当日。

连板晋级阶梯必须同时提供目标交易日、最近 5 个交易日和最近 20 个交易日三个视图，并把当前高级快照覆盖范围内的全部可评估交易日作为全样本基线。5/20 日与全样本均按“窗口成功数 ÷ 窗口样本数”计算样本加权晋级率，不得把每日百分比直接做算术平均；前端切换视图时必须始终保留全样本基线。`0→1` 表示当日首板封板率，`1→2` 以上表示前一交易日对应板高股票在下一交易日的晋级率。

题材—连板梯队卡片共用一份完整涨停成员关系，同时提供核心题材旭日图和完整梯队表。涨停事件集合是覆盖总账，`limit_ladder_daily` 提供主题材和高度；事件中缺少梯队记录的股票仍须标记为补录，禁止从图表中消失。补录记录优先使用事件中真实存在且非占位值的涨停理由作为临时主题，并以 `classification_basis=limit_reason` 披露；只有理由也不可用时才进入“待归类”。该降级规则同样适用于北交所，不因交易所而跳过归类，也不得把静态公司概念臆测成当日涨停主题。旭日图只聚合涨停家数靠前的 8 个题材，梯队表必须展示全部题材、全部涨停和覆盖审计；每只股票只按一个主题材计数，保证列合计严格等于当日涨停总数。梯队表的题材列按最高连板、涨停家数排序，高度从高到低，并显式区分 10cm、20cm、30cm 和补录状态。除“待归类”外，任何当日仅有一只涨停股的主题以及来源明确标记的“其他/独立逻辑”在梯队表合并为“独立逻辑”列，原始主题以逐股子类保留，底层主题字段和旭日图口径不改写。梯队表只允许横向题材滚动，纵向随页面自然展开；详细模式依次展示个股解读、来源涨停理由和题材催化，缺失时必须明确显示而不得生成推测性文本。

多日快照中的 `factor_attribution` 当前保存同花顺热点榜题材及其覆盖股票数，并非涨停个股原因标签归因。前端必须使用“同花顺热点题材覆盖”等准确名称；只有在输入事实明确包含逐只涨停股的原因标签并完成标准化后，才能恢复“涨停因子归因”名称。

主线强度贡献瀑布必须发布目标交易日全部已排名主线及各自的涨停广度、连板高度、梯队完整度和二板以上贡献。首名主线兼容字段只用于默认选中，前端必须提供主线选择器，不能把首名主线呈现为当日唯一主线。

行业收益相关性矩阵必须包含当前映射中具备足够收益样本的全部一级、二级行业，不得用固定数量截断二级行业。行业较多时由前端双轴缩放控制可视窗口。每个层级同时返回去除对角线和重复组合后的最高、最低 Pearson 相关行业组合排行，并显示样本交易日数；前端默认从完整矩阵展示全部行业组合的相关度前 10、后 10，选中任意行业后切换为该行业与其他全部行业的前 10、后 10，并允许恢复总排名。相关性不得表述为因果或收益预测。

QuantX 多日快照 `tickflow-quantx-multiday-v3` 只保留 `sector_flow_continuity` 作为行业资金与规则候选连续性的权威字段，其中候选集合统一为 `rule_candidates`；不再发布内容相同的 `institution_continuity`、`institution`、`institution_days` 或 `core_stocks` 兼容别名。5/10/20 日题材结构必须分别使用所选交易日窗口聚合：主线要求在窗口有效题材日中出现率不低于 60%，升温和降温要求前后半窗归一化强度差至少为正/负 8 分，不能复用最后一个交易日的生命周期标签。

顶部“题材主线”摘要必须按页面展示的多源归一化强度 `rank_strength` 降序排列，来源数只用于同分排序，保证名次与可见分数一致；完整“题材生灭与多源连续性”表仍按多源共识优先，用于表达不同的分析口径。

百日新高卡片的权威个股集合来自 `screening_candidate_daily(candidate_type=new_high_100d)`，由 `app.quantx_data.new_high_clusters` 聚合后进入 `sections.s2.new_high`。优先采用 PyWencai 返回的观察值；当该可选查询不可用时，从 TickFlow 本地日 K 计算“当日收盘价不低于此前最多 100 个交易日收盘最高值”，单股至少需要 21 个历史交易日，并将事实标记为 `source=tickflow_local_kline`、`quality_level=derived`、`is_fallback=true`。该本地计算不得放进 PyWencai 核心采集进程，以免慢速逐日网络请求超时后连带丢失晋级率等已成功数据。页面主视图展示题材概念、属性/事件、申万一级和申万二级的 1/5/10/20 交易日聚类；国企改革、央企国资、高股息、中特估、低估值、专精特新和业绩预增等宽泛所有制、风格或事件标签进入 `attribute` 维度，不得挤占默认题材排名。题材和属性当日排名优先使用一股多标签 `1/N` 加权后的 `weighted_share_pct`。点击聚类后，通过 `GET /api/quantx-data/new-high/{trade_date}/members` 按需读取完整成员证据，区分今日新高与窗口出现，并提供活跃天数、首次及最近出现日，禁止把所有成员重复塞入单日 Review 响应。交互式单文件导出可调用 `GET /api/quantx-data/new-high/{trade_date}/member-bundle` 一次读取该日所有已展示聚类的成员集合；该接口只用于传输优化，必须复用与单项接口相同的领域计算。概念标签须过滤“百日新高、趋势股、昨日、高换手”等市场属性标签。当前 `ext_data` 仅提供最新成分快照，因此历史窗口的行业与概念归属属于 `latest_ext_snapshot_proxy`，API 和页面必须显式提示，不能表述为历史时点成分。若未来接入带日期的成分表，应在领域 Service 内切换 point-in-time 映射，前端契约保持不变。

## 3. 新分析示例路径

内部盘后筛选诊断可由调用者将 `StrategyDataContext.screening_trace` 设为空字典开启，默认不记录。具备 `screen_snapshot` 候选详情的矩阵路径写入 `matrix_snapshot_candidate_pipeline` 范围、日期、策略 ID 和逐证券阶段：`strategy_no_candidate`、`basic_filter`、`pool_filter`、`missing_current_row`、`display_limit`、`displayed_candidate`。按真实候选集合和既有掩码记录；展示上限不等于入场信号被拒绝。VCP 快照同时按实际判断顺序记录首个检测器结果：`invalid_close`、`trend_ma_alignment`、`positive_returns`、`near_52_week_high`、`rs_threshold`、`turnover_percentile`、`market_regime`、`invalid_history_window`、`vcp_structure`、`short_scale_excluded` 或 `candidate`。原因表示首个未通过关卡，不代表之后关卡也通过或失败。不可用路径保留 `scope=unavailable`，不视为空失败集合。该诊断不改变筛选输出，也不属于成交证据。

日线前向观察可通过内部 `BacktestResultPolicy(include_execution_rejections=True)` 开启矩阵组合撮合的逐笔拒绝记录，默认关闭。`stats.execution_rejections` 保存实际判断日 `date`、证券 `symbol`、方向 `side`、原因 `reason`、对应 `signal_date` 与是否增加原计数的 `counted_in_execution_stats`；范围标记为 `portfolio_matrix_attempts`。记录来自撮合实际分支，不得根据候选缺失倒推拒绝。`buy_rank_cutoff` 和 `buy_already_held` 是此前未累计的跳过记录，计数标记为 false；`pending_exit` 是挂起状态计数，不是另一笔拒绝。该范围不包含策略早期过滤、未进入买入循环的末日信号或零仓位禁用场景，也不承诺其他模拟路径或分钟触发回退有逐笔记录。范围字段缺失应报告不可用，不能将空列表宣称为完整覆盖。开启记录不得改变交易、净值或现有执行计数。

基础选股与回测的总市值/流通市值过滤统一优先使用 `raw_close × total_shares/float_shares`，不得用 enriched 前复权 `close` 乘股本。原始行情/实时输入未提供 raw_close 时保留 close 即原始价的兼容契约；已有 raw_close 但值为空不回退 close。启用市值界而股本缺失、非正或结果非有限时，该行不通过；未启用市值界的策略不新增字段要求。回测依赖解析携带 raw_close，计算缓存包含此口径版本。历史研究仍须另外证明股本在目标时点可得，不能把价格公式修复等同于历史股本完整。

A 股历史回测使用 `a_share_historical` 印花税策略时，卖出成本必须按实际退出日期取值：2023-08-28 前为成交额的 1‰，自 2023-08-28 起为 0.5‰；买入侧不收印花税，退出日期缺失时拒绝计算。当前历史契约从 2008-09-19 起有明确定义，更早退出日期必须拒绝，不能静默套用 1‰。`fixed` 策略只用于显式固定费率协议和兼容既有调用。成本变化不得影响候选或信号生成；因资金复利改变后续整手数量属于执行结果，必须与结构交易序列分开比较。

假设需要“行业 20 日连续性”：

1. 从 `sector_flow_daily` 和交易日历读取最近 20 个交易日。
2. 纯函数计算出现天数、净流入方向一致性和覆盖率。
3. 缺日降低 coverage，不补零。
4. Service 返回 `{window, rows, coverage, quality}`。
5. API 增加带 `as_of` 和 `window` 的 endpoint。
6. api.ts 添加精确类型，query key 包含日期和窗口。
7. 页面提供 5/10/20 切换，并显示 coverage。
8. fixture 测试和 Playwright 验证切换、空数据和图表。

## 4. 禁止路径

- 在 React 中直接请求第三方 URL。
- 在 API handler 中读取 `raw/*.json` 并临时拼表。
- 为一个页面复制一套已有指标算法。
- 用缓存 JSON 作为回测或策略事实来源。
- 用自然日切片冒充交易日窗口。
- 把缺失来源显示为零值。
- 只检查页面能打开，不检查网络、控制台和数据语义。
