# Quants 策略迁移与研究迭代项目计划

更新日期：2026-09-05。

状态：历史完整对齐计划。用户于 2026-09-05 将目标调整为“核心思路一致，不追求 100% 还原”；当前实现和实际验证见[核心迁移验收](../../spec/quants-strategy-core-acceptance-20260905.md)。以下严格对账任务保留作参考，未执行项不视为已通过，也不再作为本轮完成门槛。

## 1. 目标与范围

先把 Quants 的五个 active 策略忠实迁移到 TickFlow，形成有版本、可复现、可逐项对账的原版基线，再另开增强版本研究策略效果。完整对齐针对原程序实际行为，不以策略名称相同、图形相似、候选数量接近或回测收益相近代替。

本项目的第一阶段包括：

- 策略配置与实际路由、依赖数据和因子、形态识别、过滤、评分、排序。
- 主/备结构、入场计划、失效价、候选状态、解释证据及其持久化映射。
- TickFlow 的正式注册、筛选、历史信号回放、适用的监控和图表接入验证。
- 为上述对齐必需的数据映射与小范围公共契约修正。

不要求复制 Quants 整个 App、UI、数据库布局或所有历史跟踪记录；必须保留策略结果的业务语义。历史记录的批量导入单独评估，不能与新策略是否对齐混为一谈。

第一阶段不优化参数、不以收益选规则、不启动实盘或持续模拟账户。原版入场计划的止损价不等于已经验证过的撮合规则，账户回测研究属于后续阶段。

### 2.1 原版问题如何处理

1. 先记录配置声明、实际消费位置、有效默认值和最终输出，不根据 YAML 推断所有配置都生效。
2. 原版硬编码、未消费参数、特殊排序、非严格连续收缩等行为进入兼容清单；忠实复现版本不得悄悄“改正确”。未生效的参数不能在界面伪装成可调参数，应标明不支持或只读。
3. 单位映射、日期解析等目标平台接入错误应在适配边界修正，使两边获得语义相同的输入，不把错误单位当成需要保留的业务逻辑。
4. 若发现原版确实依赖未来信息，保留只读参考证据，但不得把未来函数接入正式回测。标记该项阻断并提出独立修正版，由用户确认基准变更；不能同时宣称“严格原版”和“已修正算法”。
5. 对明确批准的行为改变单独编号、版本化。它不计入“严格对齐通过”，而是另一个经过说明的版本。

### 2.2 单策略验收，不要求全部完成后才能研究

默认顺序：公共基线与对照工具 → V1 VCP → V4 高旗 → V3 杯柄 → V5 回调低吸 → V2 成长趋势。五项均在范围内；V2 可以先完成路由清点，排在最后不表示遗漏。

VCP 独立通过全部迁移门槛后，可另行启动其优化任务，不必等待另外四项。但本计划当前仅安排迁移阶段，后续研究不自动执行。公共逻辑后续变化必须回归已验收策略。

## 3. 六层对齐与判定原则

| 层级 | 必须比较什么 | 不能代替验收的现象 |
| --- | --- | --- |
| L1 输入与因子 | 股票池、日期、复权、量额、资金流、财务可见性、因子数值及空值 | 日期相同，但行情来源或横截面不同 |
| L2 形态检测 | 有效性、拒绝原因、尺度、回撤腿/杯体/旗杆、枢轴、主备结构 | 两张图看起来相似 |
| L3 筛选与评分 | 每道过滤、有效参数、分项分、总分、缺失处理 | 最终分数相关性高 |
| L4 候选与排序 | 过滤前后集合、计划状态、多字段排序、同分处理、截断 | 入选数量相同或 Top-K 大部分重叠 |
| L5 状态与证据 | 准备/触发/等待/失效、发生与确认时间、价位、原因、写入重读 | 只有 entry 布尔值相同 |
| L6 运行接入 | 注册、参数更新、缓存、筛选/历史回放、适用的预览监控、重启 | 策略出现在列表、接口返回 200 |

判定规则：

- symbol、日期、布尔值、状态、数量和有业务含义的顺序要求精确一致。语义等价的枚举改名必须有一对一映射。
- 数值按字段预先制定绝对/相对容差，记录原始差值；不得在看见失败后放宽容差。容差内数值差异也不能改变阈值判断、候选入选或排名。
- null、NaN、缺列与零分别处理；不能统一填零后宣布一致。
- 若原版同分顺序未定义，先声明等价排序组，比较组间次序和组内集合。Top-K 边界切入同分组时，必须明确原版规则；不同候选集合不能借“同分”豁免。
- 所有冻结验收输入上，决策性差异必须为零。样本不足、某策略无正例或必要字段缺失，标记“未覆盖/阻断”，不能靠缩小分母得到通过。
- 严格通过只覆盖注明的数据版本、策略版本和验收范围，不声称穷尽所有可能行情，更不声称盈利有效。

## 4. 公共任务：从可复现参考到平台验收

以下任务全部待实施；每批交付应附实际命令、结果、残余差异和下一项依赖。

### M00 源码与配置基线冻结

- [ ] 记录两仓库版本、工作区相关差异、解释器及已安装依赖版本。HEAD 不能代表未提交源码；冻结必要的源码/配置快照或其他可重建版本记录。
- [ ] 清点五份 active 配置、默认路由、detector、因子构建、筛选、评分、分析补全、候选保存和信号追踪调用链。
- [ ] 输出逐参数消费表：名称、声明值、实际值、单位、消费函数、硬编码/未使用情况、影响的输出。
- [ ] 逐项确认源配置加载优先级、命令/界面覆盖值、黑名单和可选财务规则；同名旧实现不得混入参考。
- [ ] 建立“原版行为争议清单”，区分保持兼容、接入错误、待用户决定与后续增强。

交付：源基线清单、五策略路由表、参数消费表、争议清单。

验收：使用冻结输入与配置重复运行参考侧可重现；关键策略逻辑和配置来源无未解释分支。环境更新不是此任务的默认步骤。

### M01 数据与字段对照

- [ ] 定义两边适配到同一验证输入的映射，不分别读取不同日期的最新数据。
- [ ] 为 symbol、交易日期、OHLC、复权因子、成交量、成交额、上市信息、名称/ST、资金流、财务、行业及所需因子列建立字段清单。
- [ ] 每列记录来源、类型、单位、调整方式、缺失策略、实际可见时间、参与的规则与所需历史长度。
- [ ] 核对 Quants `*_for_factor`、`*_raw` 与 TickFlow enriched/原始价语义；复权锚点和公司行为一致，不能只对齐列名。
- [ ] 以隔离 fixture 验证 DATE、ISO 日期、紧凑日期字符串与 Timestamp；无效日期应显式失败或按已声明规则记录，不静默丢行。
- [ ] 按已确认来源校验手/股、千元/元等转换；资金流阈值随字段单位等价转换。禁止全库无条件乘倍率。
- [ ] 固定停牌、缺日、重复行、排序、预热与滚动窗口规则；不把上市天数、有效 K 线数和预热长度混用。
- [ ] 横截面 RS、财务加分和市值规则使用相同的当日完整参照池。仅截取候选股票会改变 RS，不能用于全链路验收。

交付：字段映射表、输入质量报告、可重复使用的隔离数据样本。

验收：样本行数、键、字段及单位逐项核对；缺数据不会悄悄变为“条件通过”。需要正式历史数据时，先明确只读来源、快照或安全导出方式；自动测试不连接生产 Quants 数据库。

### M02 建立分层差异验证工具

- [ ] 复用既有审计脚本的案例思路，建立正式可重复运行的参考输出与目标输出比较；不得把当前 8 个合成案例当成全部验收。
- [ ] 两侧独立执行、消费同一冻结输入；不能让两边都调用新实现，从而失去参考独立性。
- [ ] 将输出统一成“输入 → 因子 → 过滤 → detector → 评分 → 排序 → 状态/证据”的可比较记录，按实际调用顺序保留中间结果。
- [ ] 差异记录至少包括策略、日期、symbol、层级、字段、参考值、目标值、误差、影响、原因分类及处理状态。
- [ ] 原因分类包含数据、参数、算法、排序、时间、序列化、集成和原版缺陷；批准差异单列，不能从原始差异统计中删除。
- [ ] 人为注入枢轴偏移、资金字段缺失、过滤反转、排序变化，证明工具能检出错误。

交付：正式对照入口、规范化结果、差异明细、汇总报告及自测。产物复用项目研究存储约定；具体目录与格式实施时确定，不另建通用实验平台。

验收：相同输入两次运行结果一致；每个注入错误被对应层捕获；输入不完整时非成功退出或明确阻断，不能输出假通过。

### M03 迁移公共因子、过滤和排序语义

- [ ] 核对收益窗口、RS 横截面排名、MA、52 周位置、趋势模板、量能与财务分项。
- [ ] 复现 `screen.py` 实际使用的评分与排序链，不按未调用的专用 scorer 文件推断。
- [ ] 分别验证 V1–V5 配置差异，不将所有策略统一成同一 RS 或趋势阈值。
- [ ] 明确 TickFlow 默认价格、市值、成交额、新股过滤、数量限制对原版基线的影响，避免目标默认值悄悄增加条件。
- [ ] 将原版候选筛选和平台交易资格约束分开表达；平台限制不能被隐藏移除，也不能把其结果称为原版候选集合。
- [ ] 对未消费参数明确禁用/提示；真正新增其行为需作为独立变更，不能归为无差别平移。

交付：公共语义实现、分策略有效配置、过滤/评分/排序对账测试。

验收：同一冻结横截面内，因子与各过滤结果一致；全量排序先一致，再验证 Top-K。若复用需要改动公共执行契约，应同时证明现有策略行为不变。

### M04 正式策略接入设计与最小实现

- [ ] 为每个原版建立独立稳定 ID、名称、版本和数据要求；保留当前四个近似策略及现有用户配置。
- [ ] 优先使用已存在的正式策略契约，领域计算不依赖 Quants 安装路径、生产数据库或运行时跨仓库 import。参考工具可显式指定源仓库，交付策略必须能独立运行。
- [ ] 先确认矩阵 entry/exit 能表达什么；原版待突破、主备结构、评分和排序不能被强行压成一个布尔值。
- [ ] 若现有契约不能表达必要结果，提出最小兼容补充、默认旧行为与受影响调用方，再实现；不假设 `CandidateFilter`、`ScoringPolicy` 等设计示例已存在。
- [ ] 复用仓库、指标与派生事件边界；不复制整个策略引擎，不让 API、页面或策略直接抓供应商数据。
- [ ] 历史回放首先以正确逐前缀计算为参考，随后才做批量或增量优化；优化前后逐层结果必须相同。

交付：接入决策、独立策略版本、共享领域逻辑、能力声明和兼容测试。

验收：缺必要数据时明确不可计算；注册失败隔离；不启用迁移策略时旧功能保持原行为。

### M05 状态、计划与证据保真

- [ ] 建立原版结构有效性、候选阶段、entry 计划状态到目标字段的映射；不预先强制换成增强版的新状态机。
- [ ] 保留主/备结构、尺度、腿或锚点、枢轴、可买区、失效价、量能指标与拒绝原因；字段缺失需明确说明。
- [ ] 区分形态点发生时间、可确认时间、策略计算时间、保存时间；同一日期格式不等于相同可见性。
- [ ] 结构与策略事件进入已有派生资产体系，不伪装成客观 Market Facts；仅在必要时兼容扩充字段。
- [ ] 写入并重读后比较语义，核对版本、参数、来源、去重与重跑；补写历史事件不得覆盖其他策略版本。

交付：状态与证据映射表、序列化/重读测试、同输入主备结构对照。

验收：准备结构不被当成成交；触发不被当成实际买入；所有必需业务字段可追溯。历史全量跟踪记录导入不作为本项隐含任务。

### M06 历史逐日全链路对账

- [ ] 运行前冻结日期、股票池、字段覆盖和抽样规则；先做诊断小集，再做包含完整横截面的连续多日验收。
- [ ] 覆盖全部策略的正例、负例、阈值附近、无候选日、同分排序、缺数据及公司行为边界；不得只挑两边一致或原版入选的股票。
- [ ] 每个日期截断未来行；单股因子与横截面都按当日可用输入计算。
- [ ] 比较完整 eligible 集合、每步拒绝集合、有效结构、可执行状态、排序和最终候选；禁止只比较交集。
- [ ] 统计参考独有、目标独有、共同项、状态差异、排序差异及总覆盖。两侧都为空的日期单列，避免大量空样本掩盖差异。
- [ ] 比较整段与逐日前缀、未来数据追加/改动、股票顺序打乱后的结果；原版非确定性必须先解释，不能任意整理后掩盖。

交付：验收样本清单、逐日明细、差异闭环报告、因果性结果。

验收：冻结范围内决策性差异为零；所有必要案例有证据。若源侧财务/资金数据不足，只能给出限定层级的阶段结果，不能宣布整策略完整对齐。

### M07 应用内一致性与回归

- [ ] 验证策略列表、参数读取/保存/重新加载、重复 ID 和旧配置兼容。
- [ ] 相同策略版本、参数、输入截止日下，筛选与历史信号计算复用同一领域逻辑；回测只验证信号接线，不以收益验收迁移。
- [ ] 单股预览只展示可由单股数据计算的结果，不伪造全市场 RS、横截面评分或最终排名。不满足预览契约时明确不支持。
- [ ] 收盘策略不能在盘中用未完成日 K 冒充收盘确认。监控需要明确数据完成状态和触发时刻，不新增隐含盘中策略。
- [ ] 验证参数改变、数据版本变化、日期/资产切换后的相关缓存失效，保存后运行结果与新参数一致；隔离环境验证重启读取。
- [ ] 若改动展示，验证标签、证据图层、加载/空/错状态和旧策略切换；使用 standalone Python Playwright + Edge headless，保存必要截图并检查控制台与网络。
- [ ] 执行受影响策略、事件、预览、回测信号及公共模块回归；改前端时执行构建。

交付：集成结果、兼容性结果、必要的页面证据、性能测量。

验收：注册成功之外还有业务断言；旧策略结果无未批准变化；没有 Quants 运行时依赖。按冻结股票数/日期长度记录耗时与内存，并在实施前确定可接受预算，不能无证据宣称性能达标。

### M08 单策略冻结与移交

- [ ] 核对六层验收，列出源版本、目标版本、有效参数、数据范围、未覆盖能力和争议处理。
- [ ] 保存必要的重跑命令、参考输出、目标输出和差异报告；运行时数据不提交到源码库。
- [ ] 将策略状态从“待验收”改为“已对齐”必须引用实际证据；仅部分层通过时使用“部分对齐”。
- [ ] 确认禁用新策略即可停止使用，保留用户旧配置、旧策略及原版参考。正式替换现有监控另行确认。
- [ ] 冻结原版版本，不用后续调参覆盖它；增强版引用明确的基线。

交付：单策略验收单和版本记录。五策略全部完成后汇总项目迁移完成报告。

## 5. 各策略专项任务

所有专项任务均依赖 M00–M02；完成后必须经过 M03–M08，不以 detector 单测替代完整对齐。

### S1 VCP：首个完整样板

- [ ] **S1.1 结构复刻**：复现 short/medium/long 扫描、波段点确认、回撤提取、收缩子序列、上沿一致性或低点抬升、紧致度、主备结构选择和排序。
- [ ] **S1.2 枢轴与状态**：复现最后收缩高点作为 trigger、距离计算、量能口径、等待/试探/突破/支撑/追价过远状态及各阈值等号方向。验证窗口最高价不等于枢轴的案例。
- [ ] **S1.3 筛选与计划**：对齐原版 RS、52 周位置、多周期收益、趋势模板、实际评分与入场质量排序；核对 detector 的止损输出经分析补全后是否变化，不只读取 YAML。
- [ ] **S1.4 验收病例**：至少覆盖多次收缩、无波段的窄幅整理、扩张夹杂收缩、仅末两段、低点下移、量能阈值上下、过度追价、多个尺度竞争、样本不足、波段右侧尚未确认。
- [ ] **S1.5 端到端**：同日完整横截面的因子/候选/排序对账，跨日结构状态与事件重读，筛选和历史回放同源；先通过小集再扩展连续交易日。

完成标志：`quants_vcp_legacy_v1` 在冻结验收范围内六层通过；可作为独立研究基线，但不因此获得盈利或实盘资格。

### S2 高旗

- [ ] **S2.1 路由和参数**：使用优化 detector 的实际值，区分 YAML 声明与硬编码；不误用早期同名 detector。
- [ ] **S2.2 形态**：复现各尺度窗口、前段旗杆、低点先于高点、后续旗形、深度、量能与追价状态。
- [ ] **S2.3 筛选和输出**：复现高旗自己的 RS/高点距离及实际主流程评分、入场计划和主备结构；不直接沿用 VCP 配置。
- [ ] **S2.4 测试**：旗杆高低点顺序反转、只有旗杆无旗形、过深整理、最短窗口、量比临界、有效突破与追价过远，完成逐日全链路对账。

完成标志：高旗专项病例和 M03–M08 全通过；VCP 公共逻辑回归仍通过。

### S3 杯柄

- [ ] **S3.1 多尺度**：复现含 extended 的全部实际尺度、左沿/杯底/右沿时序、深度和柄部约束。
- [ ] **S3.2 连续性**：复现杯体中途突破、突破后的结构重置及原版无效原因，不以窗口极值代替时间结构。
- [ ] **S3.3 买点类别**：分别保留杯柄突破与杯沿支撑回测等实际类型；同一天 entry 相同但类型不同仍计为差异。
- [ ] **S3.4 测试**：无杯底、V 形反弹、左右沿次序错误、柄过深、重置前后、长期结构、多候选选择及共用筛选评分，完成全链路对账。

完成标志：每种原版实际买点都有输入与输出证据，专项和公共门槛通过。

### S4 回调低吸

- [ ] **S4.1 数据**：确认锚点净流入和近 5 日净流入的来源、单位、缺失及可见时间；资金流缺失不默认通过。
- [ ] **S4.2 锚点**：复现启动涨幅、相对量能、资金阈值、锚点搜索/选取和锚点后等待根数。
- [ ] **S4.3 回调**：复现量相对锚点与 MA20、日涨跌幅、MA10 和中线支撑约束及临界等号。
- [ ] **S4.4 测试**：锚点后 1/2/10/11 根、多个可能锚点、净流入正/零/负/缺失、跌破中线或 MA10、量能恢复，完成全链路对账。

完成标志：资金语义及正负例均通过；资金数据不足时只能保留阻断状态，不把无资金流版本标为原版。

### S5 成长趋势

- [ ] **S5.1 路由确认**：独立确认 `v2_growth_trend` 默认进入旧 `VcpDetector` 的完整条件，不按“成长趋势”名称重写，也不复用优化 VCP 冒充原版。
- [ ] **S5.2 规则清单**：从 active 配置和实际调用链列出 detector、趋势、成长/财务、评分及过滤中真正使用的项目；名称暗示但未执行的规则不添加。
- [ ] **S5.3 迁移**：复用已经证明相同的公共部分，保留 V2 独有结构、参数和排序，不将其合并到 V1 ID。
- [ ] **S5.4 测试**：构造 V1/V2 同数据结果不同的样本、V2 正负例、财务/成长相关已使用字段的缺失与时间边界、同分排序，完成全链路对账。

完成标志：有独立注册与独立验收证据，五策略覆盖表无遗漏。

## 6. 测试与差异闭环

### 6.1 验证分批

| 批次 | 输入与目的 | 通过门槛 |
| --- | --- | --- |
| A 纯函数与映射 | 合成行情、内存/临时样本；验证公式与单位 | 正负例、边界、缺失及工具检错通过 |
| B detector 与公共筛选 | 相同冻结输入；比较所有中间结果 | 数值容差固定，离散决策精确一致 |
| C 真实历史对账 | 安全快照、完整横截面、连续交易日 | 双侧集合与排序可核对，无决策性差异 |
| D 平台集成 | 隔离策略与数据配置 | 参数、缓存、事件、适用消费者与重启一致 |
| E 回归与冻结 | 本批受影响模块和已迁移策略 | 旧行为不回归，证据包与版本可重建 |

现有审计脚本仅是诊断起点。正式工具和新增测试的文件名在实施时确定；不得在未创建前记录成已可执行命令。

### 6.2 每个差异的处理顺序

1. 复现同一键上的差异，保存输入截止点和两侧原始结果。
2. 从输入层向输出层寻找第一个不同点，避免在展示层掩盖源头错误。
3. 判定目标实现错误、源数据不同、原版缺陷或未定义行为。
4. 增加失败用例后实施范围内修正；需要改变原版语义的先请求决定。
5. 重跑该用例、对应策略全链路及受影响公共回归，再关闭差异。

不可接受的关闭方式：删除失败样本、仅统计交集、关闭原版条件、扩大浮点容差以改变决策、用较好收益为差异辩护。
