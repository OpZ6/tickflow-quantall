# TickFlow 行情源替代评估与 stock-sdk 检查

> 核查日期：2026-08-24。结论针对当前项目接口与本机网络实测，不代表上游长期可用性或授权状态。

## 结论

券商接口、腾讯财经、新浪财经、东方财富和通达信协议源可以替代 TickFlow 的**部分行情能力**，但不存在同时满足“完全免费、全品种、实时+分钟+日线+复权、财务、稳定 SLA、可商用授权”的一比一平替。

更现实的免费组合是：

- 实时快照：腾讯 HTTP 或 mootdx/通达信行情服务器。
- 日线和分钟复盘：优先 mootdx；腾讯日线可作第二路径。
- 复权因子、财务、板块资金、交易日历：分别配置独立来源并做质量门禁。
- 实盘交易：使用券商交易接口；它不天然等于全市场行情供应商。

## 当前 stock-sdk 到底是什么

TickFlow 后台的 `stock-sdk（第三方行情·合规风险自负）` 是本项目内置的可选插件：

- Python provider：`backend/app/plugins/stocksdk/provider.py`。
- Node 桥：`backend/app/plugins/stocksdk/bridge.mjs`，需要 Node.js 18+ 与 `stock-sdk` 包。
- 当前上游实现：实时全市场与标的表来自 stock-sdk 的 `batch.cn`（其底层字段表现为腾讯行情）；日 K、分钟 K 和复权计算来自 `kline.cn` / `cnMinute`（当前表现为东方财富路径）。
- Docker 默认不包含它，除非显式构建 `INCLUDE_STOCKSDK=1`。

它“可以用”仅表示插件依赖与探活通过，不表示所有数据集真实可返回、字段正确或具有商用授权。设置页切换后，应逐项执行日线、分钟、实时的试拉测试。

## 本次详细检查结果

### 已确认并修复

1. 缠论 K 线补齐此前直接调用 TickFlow SDK，忽略设置页选择。本次改为通过当前日线 provider；第三方源返回空时不暗中换回 TickFlow。
2. stock-sdk 实时 `amount` 为“万元”，项目内部要求“元”；现统一乘以 10,000。
3. stock-sdk 实时 `changePercent` 为“百分数”，项目内部要求“小数比例”；现统一除以 100。
4. 单位转换不原地修改桥接 payload，并由回归测试固定。

### 本机网络实测

- 腾讯 ETF 日线 `fqkline/get`：HTTP 200，可返回前复权日 K。
- 腾讯 ETF 当日分钟 `minute/query`：HTTP 200。
- 新浪日线：HTTP 200，但样例没有成交额。
- 百度 K 线：HTTP 层可达，业务返回 403。
- stock-sdk 的东方财富日线/分钟路径：本机连接被上游关闭，返回空结果；不能据此判断所有网络环境永久不可用。

### 当前运行实例实测（端口 3018）

- 运行进程来自本仓库 `backend/.venv`，插件探活为 `available=true`，Node/stock-sdk 依赖可加载。
- 但是运行实例与磁盘偏好均显示 `daily/minute/realtime=tickflow`、`adj_factor=same_as_daily`；页面所说的 stock-sdk 切换当前并未持久化到这个实例。检查时没有替用户改设置。
- 逐数据集试拉：`daily=0`、`minute=0`、`adj_factor=0`；它们当前不能替代 TickFlow 的复盘数据。
- realtime 返回 5,548 行且 5,548 个 symbol 全部唯一：沪市 2,313、深市 2,897、北交所 338；名称、金额字段无缺失。
- 实时金额与 `price × volume` 的比值约为 100，符合 volume=手、amount=元；涨跌幅已归一为小数。唯一绝对涨幅超过 30% 的样本是北交所新股 `N信胜`（61.6%），与新股无涨跌停情形相符，不是单位异常。
- realtime 仍只有股票，不含指数和 ETF；因此即使切换成功，也不是 TickFlow 全资产实时能力的完整替代。

### 仍然存在的限制

- stock-sdk 的日线、分钟和复权上游失败时会得到空数据。项目 provider 记录警告并返回空表，调用方必须把空表视为“不可用”，不能当成同步成功。
- 复权因子由后复权/不复权收盘比合成，不等于交易所或专业供应商发布的原始 corporate-action 因子。
- 当前 instruments 只声明股票；不要用它覆盖已有 ETF/指数标的表。
- 抓取网站接口可能违反服务条款或涉及行情版权，研究可用性与合法授权是两个问题。

## 建议配置

1. 研究复盘且尽量免费：`mootdx 日线/分钟 + 腾讯实时`，加本地缓存、双源校验和失败告警。
2. 只想临时看实时盘面：可以选择 stock-sdk，但先确认金额/涨跌幅测试和全市场行数正常。
3. 需要长期自动化或商业使用：保留 TickFlow/合规供应商作为主源，免费网站接口仅作降级或交叉核验。
4. 券商接口用于交易执行时，与行情 provider 解耦；不要让下单连接承担历史研究数据仓库职责。

## 上线门禁

- 每个数据集独立探活：`daily / adj_factor / minute / realtime` 不能只测一个 `ping`。
- 校验至少一个股票、指数和 ETF；对比日期、OHLC、成交量、成交额和涨跌幅单位。
- 空结果、全零、交易日缺口、跨源偏差超阈值必须 fail closed。
- 保存 `provider / fetched_at / quality / unit` 元数据，页面展示代理或降级状态。
- 生产使用前独立确认上游服务条款、交易所许可和再分发边界。
